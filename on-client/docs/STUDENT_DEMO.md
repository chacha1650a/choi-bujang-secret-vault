# 케셰브 완성본 시연과 한계 (총공세, 학생 작성)

완성본을 처음부터 끝까지 보여 주는 순서와, 되는 것·안 되는 것을 근거와 함께 적습니다. 아래 결과는 학생이 직접 실행해 본 기록입니다. 포털 판정이 아니고, 총공세 작업은 포털에서 다시 판정받지 않았습니다.

## 1. 기록 기준

| 항목 | 값 |
|---|---|
| 작전 | 화면 틀 관제 대시보드형, 포장 없이 프로젝트 폴더에서 실행(`npm run package-app` 실행 안 함) |
| 앱 코드 기준 커밋 | `1e639667e38f7ae0c7a253965cd5935980fc7162` |
| 실행 환경 | Windows 11 Pro, Node.js v24.19.0 |
| 재현 방법 | 2026-11-06(KST)에 빈 임시 폴더로 `git clone` 한 뒤 `on-client` 에서 `ON_PORT=5196 npm run demo` 실행 |

마무리 제출 커밋은 위 커밋 뒤에 이 문서를 더하고 한 장 안내의 문장 하나를 고친 커밋입니다. 앱 코드는 위 커밋과 같습니다.

## 2. 고른 핵심 기능 3가지

| 순서 | 기능 | 왜 골랐나 | 제공 부분 | 학생이 만든 부분 |
|---|---|---|---|---|
| 1 | 내 PC 보안 대시보드 | 회사 서버 없이도 이 PC에서 실제로 끝까지 돈다 | 값을 재는 서버 `src/pc-status.mjs`, `/api/pc/status` | 카드 4개, 주의·확인 불가 판단 문구, 조회 기록, 실패 화면 (`createPcDashboard`) |
| 2 | 업무 앱 접근 판정 | 허용과 접속 성공, 거부와 요청 실패를 섞지 않는다 | 앱 목록, 요청 버튼, `/api/access` | 판정·이유·시각 표시 (`renderDecision`) |
| 3 | 보안 기록과 근거 있는 AI 설명 | 근거 없는 설명을 쓰지 않는다 | 기록 조회, AI 요청 버튼, 응답 검사 | 필터·상세, 근거 대조, 확인 불가 표시 (`renderEvents`, `renderExplanation`) |

## 3. 시연 순서와 관찰 결과

| 순서 | 누르는 곳 | 관찰한 결과 | 값의 종류 |
|---|---|---|---|
| 1 | 보호 현황 → 내 PC 보안 대시보드 → 「조회」 | 「실측값(이 PC) · 측정 시각 … · 주의 3개 · 확인 불가 0개 · 정상 3개」 | 실측 |
| 2 | 카드 읽기 | 방화벽 Private·Public 꺼짐 → 주의. 오류 건수 있음 → 주의. 실행마다 CPU·메모리 값은 달라짐 | 실측 |
| 3 | 「다시 조회」 두 번 | 조회 기록이 2줄로 쌓이고 포커스는 버튼에 남음 | 실측 |
| 4 | 업무 앱 → 세 앱 「접속 요청」 | 허용(allow), 거부(deny), 추가 확인(challenge)이 다른 문구로 보임 | 예제 |
| 5 | 보안 기록 → 「event-01 상세」 | 사건 ID·앱·세 상태가 따로 보임 | 예제 |
| 6 | 「AI 설명 요청」 | 「AI 설명 실패 · 코드: ON_AI_PROVISIONING_PENDING」, 기록은 그대로 | 실제 실패 응답(예제 서버) |
| 7 | 앱 서버를 끄고 「다시 조회」 | 「조회 실패 … NETWORK_ERROR」, 카드는 사라지고 지난 기록에 「현재 값이 아닙니다」 표시 | 실제 실패 |

3번과 7번은 같은 날 작업 폴더의 같은 코드로 확인했고, 나머지는 새 폴더에서 확인했습니다. 메모리 주의(85% 이상)는 사용량에 따라 나올 때도 있고 안 나올 때도 있습니다.

## 4. 되는 것과 안 되는 것

| 항목 | 상태 | 근거 |
|---|---|---|
| 내 PC 값 읽기와 표시 | 됨(실측) | 3장 1~3번 |
| 조회 실패와 오래된 값 구분 | 실패는 확인. 오래된 값(`PC_STATUS_STALE`)과 형식 불일치는 코드만 읽음 | 3장 7번 |
| 권한 없음·시간 초과 표시 | 코드만 읽음. 이 PC에서 그 상태를 만들지 않음 | `PC_REASONS` |
| 13~20단계 화면 | 포털 원문 검토 통과. 실행은 예제·모의 입력 중심 | `STUDENT_RELEASE.md` 4장 |
| 실제 회사 서버 연결 | 안 됨. 서버·어댑터·개인 인증서가 과정에서 발급되지 않음 | 포털 수료 안내, 기본 실행의 `ENGINE_NOT_CONNECTED` |
| 앱 안 AI 실제 설명 | 미확인. 권한 준비 중 응답만 봄 | 3장 6번 |
| 보안 조치 실집행 | 안 됨. 지원 조치 없음 | `FINAL_PRODUCT_GUIDE.md` 5장 |
| OSV 실제 조회 | 미확인. 허용 목록이 비어 `not_configured` | `STUDENT_RELEASE.md` 3장 |
| `tools/start-alekov.ps1` 실행 | 미확인. `npm run demo`·`npm start` 와 같은 서버로만 확인 | `STUDENT_RELEASE.md` 2장 |
| 설치형 포장 | 하지 않음. 이번 과정 범위 밖 | 포털 6일차 안내 |
| 화면 낭독기 사용성 | 미확인. 키보드 포커스만 확인 | 3장 3번 |

## 5. 화면의 한계

- 제공 화면을 고치지 않아 대시보드는 학생 상태 칸 안에 있고, `student-first` 배치에서도 사용자·기기 칸 다음에 보입니다. 첫 화면에서 조금 내려야 합니다.
- 상태 카드는 제공 스타일을 써서 네 칸 한 줄이 아니라 2칸씩 두 줄입니다.
- 추이는 이 창에서 직접 조회한 최근 10번뿐이고 새로고침하면 지워집니다. 저장하거나 자동으로 재지 않습니다.
- 주의 기준(CPU 90%, 메모리 85%, 디스크 여유 10% 미만, 방화벽 프로필 꺼짐, 오류 1건 이상)은 학생이 정한 단순 기준입니다. 보안 진단이나 종합 점수가 아닙니다.

완성된 보안 제품이 아니라, 본인 범위의 상태를 정직하게 보여 주는 학습용 보안 Agent 입니다.
